📋 System Overview - Complete Architecture

This diagram shows the complete MCP (Microservice Control Plane) architecture. The system separates talking (AI-generated responses) from acting (governed MCP tool execution).

🔑 Key Principles:

  • AI may speak freely - Natural conversation without restrictions
  • AI may NOT act freely - All actions go through MCP governance
  • Security by Design - Authorization → Execute → Audit
  • Complete Audit Trail - Every action logged immutably
  • Isolated Data Stores - Each MCP owns its domain

⏱️ Request Timeline - Real Example

This sequence diagram shows exactly what happens when a user submits the prompt: "Hello! Restart the service"

📝 What Happens:

  • Step 1: LLM decomposes the prompt into safe conversation + action
  • Step 2: Identity MCP checks if user is authorized
  • Step 3: Operations MCP executes the action
  • Step 4: Audit MCP logs the action result
  • Step 5: LLM generates friendly response combining greeting + success message

🎯 Decision Tree - All Possible Paths

This flowchart shows every possible decision point and outcome in the system. It helps you understand when actions are allowed vs denied.

🚦 Decision Points:

  • Conversation vs Action: LLM decides if tools are needed
  • Authorization: Identity MCP checks user permissions
  • Risk Threshold: Score >= 50 requires approval
  • Approval: Human approver must explicitly allow high-risk actions
  • Execution: Operations MCP performs the actual work

📊 Data Flow - Information Movement

This diagram shows how data moves through the system from input to output, and which databases are accessed at each step.

💾 Data Store Patterns:

  • Read-Only: Identity MCP reads user policies (no modification)
  • Read/Write: Risk MCP tracks scores and approvals
  • Append-Only: Audit MCP creates immutable logs (never deletes)
  • Isolation: Each MCP owns its database - no cross-access
